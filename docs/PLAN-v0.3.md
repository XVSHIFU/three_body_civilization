# 三体文明：品质样板与交接开发计划 v0.3

日期：2026-09-29。状态：**已记录第一轮七条批注；方向决策见D1–D6，其余细节仍供逐项审阅，不是整份计划的开发批准。**

本轮只整理项目、编写计划、准备 GitHub 交接，不继续开发玩法或重做美术。下一位开发者不得因为任务表存在，就把所有阶段自动连续执行。

## 1. 这次改变什么

目标仍是一个桌面、单人、第一人称的“观察—记录—选择保存—文明接续”体验。改变的是制作方式和扩展门槛：先证明一个小区域好看、可走、可操作，再决定扩展。

当前仓库保留技术原型，不作为成品质量标准。A/B/C三个入口方向保留，并继续优化；用户允许考虑将它们作为前端自动轮换的样式。游戏内界面、美术与模型质量仍未获认可，需要独立改进。入口概念图认可不等于实际场景认可；文件齐全、102项自动测试通过，也不等于手感、美术或完整流程通过。

原 v0.2 已要求“M1没有证明手感之前，不批量生产资产”。此前执行没有守住该门槛。v0.3 不以追加更多细节文档代替试玩，而是把每阶段的可见产物、审阅人和停止条件放在一起。

## 3. 保留哪些约束，哪些重新讨论

### 继续采用的产品边界

- 桌面单人、小型固定区域、第一人称观察与选择。手机暂只提供介绍／档案等非游玩界面。
- 观测事实、玩家假设、已确认知识分开。未采样不显示精确仪器读数，不泄漏隐藏天体总数或灾变倒计时。
- 个体存活与档案继承分开；未完成保存时，已记录事实仍保留。
- 统一世界时钟；暂停时天体、NPC、危险和保存计时均停止。
- 不扩展联机、战斗、建造、体素编辑、复杂经济或通用编辑器。

### 第一轮审阅后的方向决策

## 5. 游戏内视觉定标

先围绕方块建模起点做一个小样方向，仍按用户此前要求先看效果图、再按图实现。探索镜头包含道路、门洞、仪器、人物和HUD，便于判断整体。若成熟资产或工具能以合理成本明显提高品质，可另做一个更精细的代表样本供用户判断；只有确有比较必要才增加方向，不默认双线制作。

开发者负责把参考转成具体的轮廓、比例、材质、光照和排版，不要求用户指导建模参数。Minecraft式方块造型是可接受起点，不把当前粗糙堆块当作达标；色板、建筑比例、人物体态、材质粗细和UI字体必须协调。更精细样本获认可后才扩展该路线。

A/B/C入口也继续优化：保留各自氛围，统一主操作位置、文字层级、设置和档案入口，检查文字可读性、焦点与窄窗口表现。轮换的初步建议是每次进入首页换一款，并允许手动选择与记住偏好；若采用停留期间定时轮换，只切背景，不移动按钮，用户操作或减少动态效果时停止动画。这些是待审阅交互建议，本轮不实现。入口优化和真实3D样板分别验收，不互相替代。

视觉取舍依据：

- 玩家第一眼知道路在哪、仪器在哪；太阳和环境奇观不吞没交互目标。
- 低面数不等于随意堆立方体。用主轮廓、次级结构和少量特征控制信息密度。
- 第一名人物要有职业轮廓、姿态与工具；缩小画面仍能与建筑或普通路人区分。
- 石牌短信息可考虑场景内文字或轻量阅读层；日志可占较大面积；不可逆保存使用明确确认。不要让所有交互都变成同一个大弹窗。
- 灾变通过光线、声音、人物和局部变化表达；道路及正文仍能看清。

审批证据分三层：概念方向图 → 真实UI和明确标注的占位场景 → 实际3D游玩画面。概念图通过只允许进入下一层，不自动通过其后的层。

## 6. 一个庭院作为共同品质样板

范围固定为一段道路、一扇门、一段楼梯、一座观象仪器、一名NPC、少量环境物和必要UI。可以复用旧场地局部，但不能因为已有整城就把整城列入本轮交付。

每个资产交付：可编辑源、GLB、贴图、单位与原点、节点和动画、独立碰撞描述、交互点、来源与许可。模型导入成功与游戏内质量分别验收。

| 检查 | 实际操作 | 通过条件 |
| --- | --- | --- |
| 地面感 | 连续步行、停步、转头、上下楼梯 | 无明显漂浮、相机抖动或意外跌落 |
| 墙角／门框 | 正面、斜向、贴边通过与退出 | 不穿实体、不被不可见包围盒堵住 |
| 仪器 | 正背侧接近、远近观察、遮挡后交互 | 交互位置可理解；墙后不误触发；近处不过度穿插 |
| NPC | 迎面、侧面接近；观察站立和行走 | 不穿过玩家；职业可辨；动作枢轴和脚底正确 |
| 材质与灯光 | 正常、双日、灾变三种明确标注的检查光照 | 明暗皆可读；无明显闪烁；同一语言贯穿对象 |
| UI | 探索、阅读、返回；100%／150%字号 | 状态清楚；返回动作不需重复确认；必要按钮可达 |

穿模问题按类别记录：玩家穿墙、NPC穿玩家、相机近裁面、动画穿插、碰撞与可见网格不一致。每条附起点、动作、期望、实际、视频或连续截图。针对复现修复，不靠扩大所有门洞、禁用碰撞或缩小玩家掩盖问题。

通过门槛：用户看过固定镜头和短路线录像，并亲自完成至少一次阅读／返回和仪器操作；确认视觉方向与基本手感。未通过时只修已指出的问题，不增加资产数量。

## 7. 暂停和返回的操作合同

以下是拟议行为，需在实作前一起审阅。核心是区分用户主动返回、Esc退出、窗口失焦和不可恢复状态。

| 触发 | 预期行为 | 失败或例外 |
| --- | --- | --- |
| 探索中E打开石牌／仪器 | 暂停世界，释放鼠标，聚焦阅读操作 | 记录打开来源与原状态 |
| 点击“返回场景” | 本次真实点击内请求锁定；成功后直接继续 | 锁定失败保持暂停，显示原因和重试；不静默双层暂停 |
| 点击阅读层叉号 | 若由探索进入，按返回场景处理 | 若由暂停菜单进入，返回暂停菜单；其他暂停原因仍保留 |
| Esc、窗口失焦／隐藏 | 清空移动键，暂停全部世界计时 | 不自动抢回鼠标；回到页面后主动继续 |
| 暂停菜单打开设置，再关闭 | 回到暂停菜单 | 不因设置关闭意外恢复 |
| 保存准备阶段取消 | 只在规则允许阶段取消，反馈取消结果 | 已进入不可取消阶段时不显示误导按钮 |
| 结局、初始化失败、图形错误 | 保持对应状态，提供明确出口 | 不通过关闭面板恢复已终结或无效世界 |

验收既检查状态机，也检查实际鼠标锁定与键盘。开发控制环境的异常要保留原始错误名；用户实际移动证据优先于自动环境的泛化判断。

## 8. 三分钟玩法闭环

样板通过后才把现有模拟和规则接入：出生 → 找到仪器 → 留下事实 → 看见异常 → 选择继续或保存 → 因果结算 → 下一文明看到继承。

第一版至少两条真实游玩路线：及时完成保存；未完成保存。不得只切换结算文本。仪器记录、个体结局、城市结局和继承分别来自真实状态。

用户已选择“个体保存大体与原著一致”的方向。开发者在制定具体行为前核对相应原文依据，将原著描述、当前实现、拟议改编分开说明，不把现有保存设施、计时或档案继承规则直接称作原著设定。优先让玩家理解保存对象、适用条件、恢复条件与失败后果；不要求用户先设计一套额外的个人价值系统。目前档案在死亡后保留，个体与知识的差异仍需在试玩中表达；若确实无法形成可理解的选择，再提出最小调整，不偷偷添加饥饿经济、惩罚或删除继承。

闭环退出条件：

1. 两条路线从新档开始实际走通，有操作和结果记录。
2. 玩家能解释当前目标、设施位置、保存与继续的代价以及结局原因。
3. 未观测信息不进入HUD或结算；已记录事实能跨文明继承。
4. 暂停、刷新和保存失败不造成重复结算或数据丢失。
5. 至少一名未被口头引导的试玩者完成主循环；问题先修复再扩展。

正式轨道继续复用现有筛选证据，但场景版本、固定步、时标和气候阈值变更后要重新核对。演示光照、压缩时标与正式模拟必须区分。路线可达性包含转角、楼梯、操作和容错，不用直线距离代替。

## 9. 分阶段任务与停止条件

| 阶段 | 唯一主要交付 | 谁验收／证据 | 通过后允许什么 |
| --- | --- | --- | --- |
| P0 当前交接 | 可克隆原型、问题基线、v0.3草案、资产来源、复现命令 | 开发者验证新目录恢复；用户审阅计划 | 只开启下一张已确认任务 |
| P1 方向与工具 | 一个方块方向小样；按具体疑点评估工具，必要时增加一个更精细样本；明确入口优化方案 | 用户看效果图；新工具若采用，须有真实导出与运行证据 | 按认可方向制作一个庭院样板 |
| P2 品质样板 | 门／梯／仪器／角色／HUD与阅读返回 | 用户实际试玩；固定画面和路线录像 | 批量制作有限模块 |
| P3 三分钟闭环 | 两条真实路线及可理解的选择后果 | 用户与首次试玩者；存档及因果记录 | 扩展10–15分钟和六名NPC |
